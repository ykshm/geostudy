# 文体改稿の手引き(第4版までの44章の声と注を改める)

本書の読み手は、この改稿を行うClaudeのセッション——あなた——である。第5版のCONCEPT.md、改訂されたWRITING.md、authors/声の設計表.md の雛形がマージされていることを前提にする。マージされていなければ、改稿を始めず、依頼者に確かめる。紙面の決まりは CONCEPT.md / WRITING.md が正本であり、本書は繰り返さない。本書が定めるのは、改稿の目的と、工程の順序と、章を触るときの規則だけである。

## 0. 大目的

この読み物は、ふたりの読書会で、章の原文が一段落ずつ引用されて読まれる。読者ふたりは、章の冒頭のプロフィールで著者を知っていて、著者の癖をからかう。その席で、引用を聞いただけで「この人だ」と分かること。それが著者を置いた目的であり、この改稿の目的である。

第4版までの44章は、専門のレンズでは書き分けられていたが、声は一つだった。11人の著者の文末の分布はほぼ同一で(である16〜20%、だ0〜3%、敬体ゼロ)、平均文長は全員30〜40字に収まり、全員が同じ温度で断定し、章の開き方は「具体物を置く→つまり→この章では順に見ていく」の一型だった。読者ふたりから見れば、11人は一人である。これを、11人にする。

同時に直すものが一つある。注が、著者の声で「なぜ」に答える段ではなく、本文の数字を写して出典を添える検証の帳簿になっていた(後期の章では注が全体の半分近くを占める)。44章を二度触らないため、この改稿で一緒に直す。

改稿の目的でないもの: 事実を足すこと、構成を変えること、章を良くすること。改めるのは声と注の形だけであり、紙面が言っている事実と、節と段落の並びは、そのまま残す。

## 1. 工程の順序

順序を変えない。理由: いまの装置のまま章から手を付けると、44章が第二の一つの声に揃うだけである。

工程0 道具 → 工程A 声の設計(全著者いっぺんに) → 工程B 試作(一人二章) → 工程C 本改稿(著者順) → 再点検(10節) → 工程D 締め

各工程の終わりに依頼者へ報告し、確認を得てから次へ進む。改稿は一つのセッションで完結させ、文体の点検は同じセッションからサブエージェント(点検役)に出す。理由: 書き手は自分の家の声を聞き分けられない。点検は、執筆の文脈を共有しない相手にさせる。

## 2. 工程0 道具

scripts/ に三つ作り、既存の章で動くことを確かめてから先へ進む。

- `scripts/factdiff.py 旧 新` — 二つの章ファイルから、数字(桁区切り・小数・%・年・時刻を含む)、カタカナ語(二文字以上)、英字列、「」内の語を抜き出し、新にあって旧にないもの、旧にあって新にないものを列挙する。章の冒頭のプロフィールと目次は比べない(正本から写すものなので、対応表に擬似の組を置かない)。-check に置いた表記の対応表(「約4割」↔「およそ40%」のような揺れ)を読んで、対応する組は差分から除く。片側から何も抜き出されない組(「X ↔ (検証記録へ移した)」)は、表記の揺れではなく移した・落とした事実として別に一覧に出す——-check の「落とした事実」「移した事実」と一致させる。参考として、両方にあるが回数が変わった数字も出す(一部だけ落とした箇所を探すため。終了コードには数えない)。見出しに「論点」「再点検」「検査」「点検」を含む節の中の「↔」の行は、記録の説明なので対応表として読まない。
- `scripts/voice.py 章 [--compare]` — WRITING.md 4節2(a)の測定。本文(見出し・目次・表・図の行と説明・注を除く)と注を分けて、文数、平均文長と散らばり、文末の分布(である/だ/た/る・い/敬体/体言止め)、段落数と平均・最長段落長、一人称・括弧・ダッシュの千字あたりの回数、冒頭段落の型(場面/数字/地図/問い/引用/その他)を出す。測定の約束: 注の合図(【注N】)を落としてから文を切る(落とさないと「〜た【注3】。」が体言止めに数えられる)。文末の括弧書きは括弧の前の語で、「〜のだろう」は疑問の語を含めば問いとして、「積んである」「欄まである」は動詞の「る・い」として数える。一人称は「」『』の中を数えない。ダッシュは二倍ダッシュ(——)だけを数える。「死んだ」「泳いだ」のような撥音便・イ音便の過去形は「た」に数える。`--compare` は authors/index.md を読み、同じ測定を全章と archive/v1/ の全章に掛けて、指定章から各章までの距離(文末分布の差の和と、標準化した文長の差の和)を近い順に、著者名とともに出す。archive/v1/ の章には「(旧)」、-check に改稿の記録が無い章には「(未改稿)」を付ける。距離の文長の項は固定の11字で割る(比べる章の顔ぶれで二章の間の距離が動かないように)。出力の末尾に、旧版を除いた最近傍と、6節2の(a)(b)の判定を出す。
- `scripts/tenken.py` — 点検役に渡す文面を組み、掛ける前の機械検査も担う。四つの用法。節の番号の 0 は前書き(第1節より前の本文。章の冒頭)を指す。
  - `tenken.py mekakushi 章 [--key 答えファイル]` — authors/声の設計表.md から全著者の名前と声の軸(文体・文の長さ・文末の偏り・一人称・言い切り・脱線・冒頭の型・締めの型)だけを読む。専門・音叉・解禁は渡さない。章から本文の段落三つ(冒頭=前書きと第1節から・中ほどの節・終節から各一つ。図の行と説明、表、見出し、プロフィールは抜かない。【注N】の合図は落とす。節番号や他の章への言及を含む段落は、ほかに候補があれば抜かない)と注一つ(声の段があるもの)を抜く。当て馬として、authors/index.md で別の著者に割り振られた章のうち -check に改稿の記録(「## 改稿」の見出し)があるものから本文の段落二つを抜く——一つは文末の分布と平均文長で最も近い他の著者の章から(紛らわしい声を必ず混ぜる)、一つは無作為に別の著者から。全部を無作為に並べ替えて番号を振り、点検役への依頼の一文と答えの書式を添えた文面を stdout に出す。番号と出所の対応表は --key のファイルに書き、stdout には含めない。
  - `tenken.py shogo 章 節 [--taisho] [--sai]` — 設計表の当該著者の行、その著者の文体カードの物差しの節(声・この人はこう書く・台帳からの解禁・観測された癖。更新記録・代表章・調律は載せない)、文体台帳の全文、当該節の本文と注を、一つの文面に組む。文面の頭に、この一節の章の中の位置(前書き/途中の節/終節)、開き・締めの軸を判定するか(開き=章の冒頭、締め=終節だけ。5節)、章の本文の平均文長と区分(文の長さの軸はこれで判定させる)、その一節の本文の機械の測定(参考)を置く。前書き(0)には、前書きの合図が呼ぶ注(紙面では第1節の注の下にある)を添える。終節には参照として章の冒頭の段落を添える(環状構成と、冒頭の問いへの答えを見るため)。図の行と説明文は据え置き部分なので省略の印に置き換える。文体台帳は項目行だけを載せる。--taisho を付けると末尾に「対照を求める」と足す。--sai は以前の減量版の名残で、いまは初回と同じ文面になる。文体カードも台帳も初回と再照合で同じものを載せる——回によって物差しが違うと、同じ文面への判定が入れ替わる。
  - `tenken.py sample 段落ファイル…` — 工程A用。設計表の声の軸と、著者ごとの試し書きの段落(ファイル名に著者のローマ字名を含める)から、目隠しの文面と答えを組む。
  - `tenken.py selfcheck 章 [節]` — 照合役に掛ける前の機械検査。節を省くと前書きを含む全節を見る。指摘として数える(終了コード1)もの: 400字を超える段落(本文と注の声の段)、文体台帳と当該章の -check の臨時規則から拾った禁句の一致、旧版(archive/v1/)より少ない段落・旧版と違う注の番号の並び・違う節の並び。臨時規則からは、禁止の言葉(使わない・しない・避ける・封印…)を含む文の「」だけを拾い、「今回の軸」「声の確認」の行と、「A」で開く・「B」に置き換える のような使う側の語は拾わない。「である。」の禁句は「積んである。」の中では数えない。置き場所の規則(「A」を1節末尾に置かない)の語と、頻度の癖の語(「のである」連発)は参考として回数を出す。参考情報: 節ごとの文末の内訳・70字を超える文・ダッシュの数・段落末の決め文句・留保の無い称号語・節や章への言及(「5節で見た」「次の節」「別の章」。図の説明文も見る。「この章」「この節」と注の番号、出典の「3.1.3節」は拾わない)・図の説明文の禁句・旧版より多い段落(割ったなら -check に段落の対応表)・設計表の文末の語が一つも無い段落と注(目隠しで外れやすい)。機械で見つかる項目に照合役の往復を使わない——指摘が残る文面を照合役に回さない。
- `.claude/agents/geostudy-mekakushi.md` と `.claude/agents/geostudy-shogo.md` — 点検役の定義。リポジトリに同梱してある。どちらも tools をファイルを読めない害のない道具の候補列(NotebookEdit, TodoWrite, TaskCreate, ListAgents)にして Read/Glob/Grep/Bash を持たせず(allowlist を空にするとサブエージェントは起動しないので、認識される名前が一つは残るよう複数並べてある)、omitClaudeMd で CLAUDE.md も渡さない。この環境(リモート)で認識される道具名: 候補列のうち NotebookEdit のみ(2026-09-17 実測。他の名前は黙って落とされるが、一つ認識されれば起動する)。動作を確かめる: 既存の章で `tenken.py mekakushi` を組み、目隠し役に渡し、書式どおりの答えが返り、汚染と言われないこと。点検役のモデルは書き手と同格を使い、下位のモデルに下げない——同じ文面で比べた実測(2026-09-17)では、目隠しの正答は書き手同格3/4に対し Opus 2/4・Sonnet 1/4・Haiku 1/4で、崩れるのはいずれも近い声の弁別(千々石/戸川)。照合役も、Sonnet は規定の過剰に文字通りな読みと帳簿判定の誤り、Opus は据え置き部分や設計どおりの実況・題材の幅まで否に数える過検出で、書き手同格が全軸合とした節に5軸の否を出した。門番を下位モデルにすると偽の否で修正往復が増え、かえって高くつく。節約は文面の側(selfcheck・--sai・並行実行)で行う。
- archive/v1/ を作る(無ければ)。
- site/build.py は Python の markdown パッケージを使う。環境に無ければ `pip install markdown` で入れてから掛ける。

## 3. 工程A 声の設計

1. authors/声の設計表.md を、11人ぶん一度に埋める。一人ずつ作らない。第4版の実測(表のファイルに書いてある)から離す。
2. 距離の条件(WRITING.md 5節)を満たすまで組み替える。敬体の著者・留保する著者・脱線する著者を各一人以上。音叉は系統を散らす。
3. 声はレンズと矛盾しない範囲で振る。専門・経歴・筆が乗る話・やらないことは、原則として変えない。変えるのは声の欄だけである。ただし第4版のプロフィールに書かれた声の言葉(「断定を恐れない」「文は短め」など)は、設計表に合わせて書き直す——第4版のそれは、実測と合っていなかった。
4. 場の制約: どの声でも段落は目安400字まで。文の長い声には短い段落を。
5. 著者の正本(authors/*.md)を書き直す。声の欄は、読者ふたりが引用を聞いて分かる言葉で数行。楽屋の具体値は文体カードへ。
6. 文体カードを書き直す。声の欄、音叉(系統つき)、台帳からの解禁(一項目まで)、この声を出す具体の手。「観測された癖」の欄は残す——レンズ側の癖は今後も有効である。代表章の指名は、改稿済みの章ができるまで空欄でよい。
7. 設計の段階の目隠し: 各著者につき、設計表の声で試しに書いた段落を一つずつ(題材は任意、事実は書かなくてよい。ただし著者の専門の題材は避ける——題材で当たっては検査にならない)ファイルに置き、`tenken.py sample` で文面を組んで目隠し役に渡す。11人中8人以上当たるまで設計に戻る。当たらなかった組が、設計表を組み替える材料である。
8. 依頼者に設計表・正本・文体カードを見せ、確認を得てから工程Bへ。正本の書き換えを章の写しに反映する作業(bash)は、章を改稿するときにその章ごとに行う。

## 4. 工程B 試作

- 著者を一人選ぶ: 振り幅が最も大きく、章が二つ以上あり、読書会で読みかけの章を持たない者。読みかけの章は依頼者に聞く。
- その二章を5節の規則で改稿し、6節の検査を全部通す。この試作で、照合役の指摘の粒度と、目隠し役の当たり方を見る。照合役が毎節「否」を出すなら、設計表の値が書き手に写せていないか、規定が曖昧かのどちらかで、後者なら設計表の語彙を直す。
- 読書会で読める段落かどうか、依頼者に確かめる。読みにくければ設計に戻り、その著者の行を直してやり直す。
- 通ったら工程Cへ。この二章は本改稿に数える。

## 5. 改稿の規則(一章ごと)

- 読むもの: CONCEPT.md、WRITING.md、その章のシリーズの series.md、著者の正本・文体カード・設計表のその行、その著者の改稿済みの章2本(無ければ試作章)、旧版の章と -check。読む量は定数に保つ。
- 版の保存: 旧版を archive/v1/text/<series>/<name>.md にコピーする(初回のみ。同名があれば済み)。旧版の -check も同じ場所に写す。旧版の img/ は共有でよい。
- 手順: 旧版を一節ずつ読み、同じ節を、同じ段落数で、その著者の声で書き直す。書き直した節は、まず `tenken.py selfcheck 章 節` の機械検査を通し、指摘を潰してから照合役へ回す。照合は `tenken.py shogo 章 節` で文面を組んで照合役に渡す——節の照合は互いに独立なので、章を書き切ってから全節ぶんを並行で走らせてよい(壁時計はこれで数分の一になる)。指摘はまとめて処理してよいが、修正を出す前に必ず8軸と臨時規則で自己照合する——直しが別の軸を壊す手戻り(開きの音を消す、決めの一文を増やす)はここで起きる。前書き(第1節より前の本文。章の冒頭)も一つの節として、`selfcheck 章 0` と `shogo 章 0` で掛ける。再照合の門は前書きと終節(6節3')。前書き(無ければ第1節)と終節は `--taisho` を付けて捨て札も見る——差が小さければ、まだ動いていない。図の行と説明文は据え置く(声で言い直してよいが、図を開かなくても通じる具体性は落とさない)。プロフィール表・位置の図・目次の写しは変えない。
- 開きと締めの型の範囲: 設計表の冒頭の型は章の開き(前書き。前書きが無ければ第1節の頭)に、締めの型は章の締め(終節の末尾)にだけ当てる。途中の節の頭と末には当てない——倣うのは著者の自由だが、求めない。途中の節の末は、台帳の構図(警句・決めの一文で締める偏り。事実か場面で終える節を過半に)で見る。終節の末尾に置いた締めの型どおりの一文(総括・換算・最短の答え・問い・予告)は、決めの一文・警句・家の声に数えない。照合役にもこの範囲で判定させる(tenken.py が文面の頭で位置と判定する軸を渡す)。
- 型の材料が旧版に無いとき: 冒頭と締めの型が求める材料(寸法・予算の数・速さの数・原語)が旧版に無ければ、事実を足さずに、章の中にある事実で型の形を満たす(速さの代わりに章の中の長さや年数を人の尺に当てる、など)。照合役が材料の不足で否を出したら、-check に記録して通過とする。
- 文体カードは、一つの章の照合の途中で書き換えない(照合役に渡る物差しが回ごとに変わり、判定が入れ替わる)。学びは章を納めるときに更新記録へ書く。カードの声・この人はこう書く・観測された癖の欄を書き換えたら、その著者の照合の往復は数え直す。
- 事実: 足さない。落とさない。旧版が言っている数字・固有名詞・年・出典を全部残す。どうしても声に載らない事実は落としてよいが、-check に「落とした事実」として理由つきで残す。新しい事実を足すのは禁止——検証していない言い回しが混じる事故は、ここで起きる。factdiff の「新にあって旧にない」は、-check の対応表で読み替えられる表記の揺れを除いてゼロでなければ出さない。次の三つは足したことに数えないが、-check に記録する: (1) 旧版の誤りの訂正(CONCEPT.md 3節の通常の編集。出典と一緒に「訂正:」として書く)、(2) 本文と注のあいだで事実を移すこと(「移した事実:」として書く。地名を動かすと site/geo/ の地図のピンが外れることがあるので、site/build.py の警告を見て JSON を直す)、(3) 章の中の数だけから出した換算・比(式を -check の「換算と算術」に書き、対応表に「計算: 元の数 ↔ 結果」の組で置く)。落とした事実・移した事実を表記の対応表にまぎれ込ませない——factdiff は片側だけの組を別に一覧に出す。書き手の動作・視線・場面の細部(歩いた、見上げた)は声の手として足してよいが、土地の事物・人の経歴・数・名・年は足さない。プロフィールの経歴を本文の挿話に写さない。足した場面の細部は -check に記録する。
- 構成: 節の数・題・順を変えない。段落の数を変えない——読書会の栞は段落の番号で位置を指している。400字を超える段落を割らざるを得ないときだけ増やしてよく、その場合は -check に新旧の段落の対応表を残す。
- 注: 番号と数を変えない。各注を、声の段と出典行に分ける(WRITING.md 2節)。声の段は、本文が言わなかったこと——「なぜ」の答え、拾う話題、著者の見立て——だけ。本文の数字の再掲と「〜は○○による」の帳簿は -check の検証記録へ移す(-check に無ければ足す。検証は済んでいるので、記録を移すだけでよい)。出典を示すほかに言うことのない注は一行にする。旧版の注が持っていた「なぜ」の答えは、一つも落とさない。
- 章の独立、他章への参照の禁止、安全のための断り書きの禁止は、従来どおり。章の中の節番号の参照(「5節で見た」「(3節・注4)」「次の節で」)も書かない——目隠しで汚染と判定される。本文の「(注3)」は注を呼ぶ合図の書き方の一つで、書いてよい。
- 文長を区分に収めるために文を割るとき、割った後ろの文を「それは」「これは」のような指示語の主語で始めない(溜めの一文になり、家の声と読まれる)。
- 臨時規則は、その章の -check の中で完結させる。禁句は「」で具体に列挙し、「mi の臨時規則の禁句すべて」のような参照で済ませない(selfcheck はその章の -check しか読まない)。設計表の行を写す「声の確認」と「今回の軸」の行は selfcheck が禁句として拾わない。旧版の臨時規則は、第5版の設計表・カードと食い違う項目(解禁された言い回し、敬体の語尾など)を除いて引き続き有効。
- プロフィールの写しは、書き直した正本からbashで入れ直す。
- -check の先頭に「## 改稿: 日付 第2版(声の改稿)」の見出しで、設計表の行・落とした事実・移した事実・訂正・段落の対応・検査2の結果を足す(道具は「## 改稿」で始まる見出しで改稿済みの章を見分ける)。執筆日と検証記録は残す。
- 文体カードの更新記録に一行足す。代表章が空欄なら、この章を指名する。

## 6. 検査(一章ごと)

検査は、紙面に出す最後の文面に対して行う。順序: 照合(3')→ 目隠し(3)→ selfcheck・factdiff(1)・voice.py(2)・段落(4)・通読(5)・build(6)。最後の検査の後に本文を変えたら、変えた節の selfcheck と照合、目隠し、factdiff、voice.py を掛け直す——紙面に出る文面は、どの検査も見た文面にする。

1. factdiff: 新にあって旧にないものが、表記の揺れを除いてゼロ。旧にあって新にないものと、片側だけの対応の一覧が、-check の「落とした事実」「移した事実」と一致する。
2. voice.py: (a) 章の本文の平均文長が、設計表のその著者の区分に入る(短=30字未満、中=30〜40字、長=40字超)。(b) `--compare` の最近傍が、自分の著者の改稿済み章であること(「未改稿」の章は比べる相手に数えない)。archive/v1/ の自分の著者の旧版が最近傍なら不合格——旧の声が残っている。自分の著者の改稿済み章がまだ無いとき(一章だけの著者、著者の最初の一本)は、(a)に加えて、自章の旧版が近い順で10位以内に無いことで代える。設計表の声が第4版の分布に近い著者(る・い+である など)では、他の著者の旧版が最近傍になることがあるので、それだけでは不合格にしない。最近傍が、設計表で文の長さの区分が同じ他の著者の章で、文末の分布だけで比べた最近傍が自分の著者の改稿済み章なら合とする——同じ区分の著者どうしでは、文長の差は区分の中の揺れであって声を見分ける材料にならない(voice.py が判定を出す)。距離の差が小さい順位の入れ替わりを戻すために文を書き換えない。
3. 目隠し: 最終稿で `tenken.py mekakushi 章 --key 答え` を目隠し役に渡し、答えと突き合わせる(WRITING.md 4節2(b))。章の合否は、自分の四つのうち三つが当たること。当て馬がこの著者に帰されたら、その組(当て馬の著者×この著者)と段落を -check の「## 規定側の論点」に記録する——当て馬の取り違えは当て馬の側の声の問題でもあり、この章の本文では直せないので、それだけでは章を不合格にしない。同じ組の取り違えが二人以上の章、または一人の著者の二章以上で記録されたら、設計表の近い組として依頼者に報告する(論点帳1-10)。落ちたら、外れた段落の声を直し、新しく組んだ文面で掛け直す(抜き出しは毎回変わる)。掛け直しは2回まで——3回落ちたら、設計表の近い組の問題として依頼者に報告する。外れやすいのは注の声の段(短く、署名の手が無い)なので、注にも一人称・文末・言い切りの手を置く。
3'. 照合: 章を書き切ったあと、前書き(`shogo 章 0`。前書きが無ければ第1節)と終節をもう一度照合役に掛ける(2回目以降の文面は `--sai` でよい)。合格の基準は次の四つが無いこと——8軸の否、文体台帳の該当、帳簿の注、家の声。開き・締めの軸は5節の範囲で見る(文面が「対象外」と書いた軸は判定しない)。それ以外の観測(決めの一文の数え方、注の見立ての扱いなど、規定の解釈に属する助言)は、直すか、-check に理由を記録すれば通過。据え置き部分(図の行と説明文・節題・注の呼び出し順)は文面から省かれているか照合の対象外で、指摘が出ても記録のみでよい。照合役は掛けるたびに別の限界事例を見つけるものなので、「あらゆる指摘がゼロ」を追わない。往復の数え方: 全節の初回の照合は数えない。前書きと終節のそれぞれに、再照合を3回まで。途中の節は門ではない——途中の節を直して掛けたときは、初回の後に直し、確認の照合を1回だけ掛け、確認で新しく出た指摘は直さずに -check に記録して止める。途中の節の合否は、直した段落についてだけ見る。3回目の指摘を直したら、直した版に確認の照合を一度だけ掛ける——確認で新しく出た指摘は直さずに -check に記録して止める。指摘が審査のたびに入れ替わるのは、直すのが文面ではなく規定側(設計表・カードの語彙)である合図なので、-check の「## 規定側の論点」に書く(7節)。
4. 段落: 最長段落が目安を超えていない。旧版より少ない段落が無い(selfcheck が数える)。
5. 通読: 事実の通り。「なぜ」が閉じている(改稿で答えが消えていないか)。台帳と臨時規則の照合(解禁項目を除く)。
6. site/build.py が警告を出さない。

結果を -check に記す。

## 7. 工程C 本改稿の順序

- 著者順に進める。一人の全章を続けてやり、次の著者へ。章順(州順・シリーズ順)ではやらない。理由: 声は連続して書くうちに定まり、文体カードに積める。
- 著者の順は、試作の著者、次いで authors/index.md の著者一覧の順。ただし、読書会で読みかけの章を持つ著者は最後に回す。
- 一つの章は一度しか触らない(10節の再点検で、点検に落ちた箇所を直すのは除く)。著者の途中で設計表を直したくなったら、直してよいが、その著者の改稿済みの章を全部やり直す。
- 一人分終わるごとに納品し、報告する: 声がどう変わったか(voice.py の前後)、落とした事実、段落の対応、目隠しの結果、直したい点を見つけたが直さなかった箇所。マージは依頼者の指示を待つ。
- ブランチは著者ごとに切る。mainには直接コミットしない。
- 著者ごとのセッションを並行で走らせるとき: 共有の規定(設計表・文体台帳・本書・scripts/・点検役の定義)と、ほかの著者の章とカードは、そのセッションでは直さない。規定側の論点(6節3'で規定を直したくなったもの、当座の解釈を置いたもの、道具の不具合、依頼者に判断を仰いだもの)は、その章の -check に「## 規定側の論点」の見出しで一行ずつ書き、納品の報告にも挙げる(一つのファイルに書き足すと、並行のブランチどうしが衝突する)。当座の解釈は照合役には見えない——照合役に渡るのは設計表の行・カードの物差しの節・台帳と一節だけである。論点は、全セッションが納めてから一つのセッションで集めて規定を直し、10節の再点検に掛ける。並行の改稿中の章(-check に改稿の記録がまだ無い章)は --compare の比べる相手に数えない。

- 読書会への引き継ぎを依頼者に報告する: 読了済みの章は旧版で読まれたこと、既存の転写の照合(場の道具の check)は旧版に対してしか通らないこと、旧版の所在が archive/v1/ であること。

## 9. やってはいけないこと

- 工程の順序を変える。設計表を埋めずに章から始める。
- 事実を足す。構成を変える。段落を減らす。
- 章の途中で声を変える。
- 章順で進める。
- 注を声の段にするときに、「なぜ」の答えを削る。
- 旧版を消す。
- 声を振るために、読みにくくする。
- 点検役に渡す文面に、著者名・章名・自分の説明を足す。tenken.py の出力をそのまま渡す。
- 点検役に直させる。捨て札を紙面に使う。
- 照合役の指摘を、処理せずに次の節へ持ち越す。
- 最後の照合・目隠しの後に本文を変えて、掛け直さずに出す。
- 並行の改稿中に、共有の規定(設計表・台帳・本書・scripts/・点検役の定義)を直す。
- 測りの順位を合わせるためだけに文を書き換える。落とした事実を表記の対応表に隠す。

## 10. 再点検(工程Cの後、工程Dの前)

工程Cの記録(44章の -check の検査の記録、文体カードの更新記録、納品の報告)を集めると、11人ぶんのセッションで同じ不備が繰り返し挙がっていた。集めた一覧と、それぞれをどう直したかは docs/改稿の論点帳.md にある。道具と規定は2026-09-23に直した。工程Cの検査は直す前の道具と規定で行われたので、全44章を直した道具と規定でもう一度点検する。改稿のやり直しではない——紙面を直すのは、点検で落ちた箇所と、論点帳の「章ごとの持ち越し」に挙げた箇所だけである。

一人の著者の全章を一つのセッションで行う。著者どうしは並行でよい(7節の並行の決まりに従う)。

1. 読むもの: 5節の「読むもの」に加えて、論点帳の「章ごとの持ち越し」のその著者の行と、各章の -check の改稿の記録・検査の記録。
2. 機械の点検(点検役は使わない)。章ごとに:
   - `tenken.py selfcheck 章`(前書きを含む全節)。指摘をゼロにする。参考の「節・章への言及」は言い換える(事実は変えない)。
   - `factdiff.py archive/v1/<章> <章>`。6節1。
   - `voice.py 章 --compare`。6節2の(a)と(b)。
3. 文面の直し: 2で落ちた箇所と、持ち越しに挙げた箇所だけを、5節の規則の範囲で直す(事実・節・段落の数・注の番号は動かさない)。文長を区分に収めるときは、長い文を割るのを基本にする——言い換えで事実を落とさない。
4. 照合: 前書き(`shogo 章 0 --taisho`。前書きが無ければ第1節)と終節(`shogo 章 N --taisho`)を照合役に掛け、6節3'の往復で処理する。3で本文を直した途中の節があれば、その節も掛ける(初回→直し→確認1回。確認で新しく出た指摘は記録して止める。6節3')。
5. 目隠し: 最終稿で `tenken.py mekakushi`。6節3。当て馬の一つは測りで最も近い他の著者から出るので、工程Cより厳しくなっている。
6. 2をもう一度、最終稿で。site/build.py の警告ゼロ。
7. 記録: 各章の -check に「## 再点検: 日付」の見出しで、2〜6の結果と、直した箇所(節・段落と理由)を書く。改稿の記録(「## 改稿」)は消さない。文体カードの更新記録に一行。新しい規定側の論点は -check の「## 規定側の論点」へ。
8. 納品: 著者ごとに一つのブランチ、一つのPR。報告は、章ごとの合否(照合・目隠し・文長の区分・最近傍)、直した箇所、残した論点。
