# 文体改稿の手引き(第4版までの44章の声と注を改める)

本書の読み手は、この改稿を行うClaudeのセッション——あなた——である。第5版のCONCEPT.md、改訂されたWRITING.md、authors/声の設計表.md の雛形がマージされていることを前提にする。マージされていなければ、改稿を始めず、依頼者に確かめる。紙面の決まりは CONCEPT.md / WRITING.md が正本であり、本書は繰り返さない。本書が定めるのは、改稿の目的と、工程の順序と、章を触るときの規則だけである。

## 0. 大目的

この読み物は、ふたりの読書会で、章の原文が一段落ずつ引用されて読まれる。読者ふたりは、章の冒頭のプロフィールで著者を知っていて、著者の癖をからかう。その席で、引用を聞いただけで「この人だ」と分かること。それが著者を置いた目的であり、この改稿の目的である。

第4版までの44章は、専門のレンズでは書き分けられていたが、声は一つだった。11人の著者の文末の分布はほぼ同一で(である16〜20%、だ0〜3%、敬体ゼロ)、平均文長は全員30〜40字に収まり、全員が同じ温度で断定し、章の開き方は「具体物を置く→つまり→この章では順に見ていく」の一型だった。読者ふたりから見れば、11人は一人である。これを、11人にする。

同時に直すものが一つある。注が、著者の声で「なぜ」に答える段ではなく、本文の数字を写して出典を添える検証の帳簿になっていた(後期の章では注が全体の半分近くを占める)。44章を二度触らないため、この改稿で一緒に直す。

改稿の目的でないもの: 事実を足すこと、構成を変えること、章を良くすること。改めるのは声と注の形だけであり、紙面が言っている事実と、節と段落の並びは、そのまま残す。

## 1. 工程の順序

順序を変えない。理由: いまの装置のまま章から手を付けると、44章が第二の一つの声に揃うだけである。

工程0 道具 → 工程A 声の設計(全著者いっぺんに) → 工程B 試作(一人二章) → 工程C 本改稿(著者順) → 工程D 締め

各工程の終わりに依頼者へ報告し、確認を得てから次へ進む。改稿は一つのセッションで完結させ、文体の点検は同じセッションからサブエージェント(点検役)に出す。理由: 書き手は自分の家の声を聞き分けられない。点検は、執筆の文脈を共有しない相手にさせる。

## 2. 工程0 道具

scripts/ に三つ作り、既存の章で動くことを確かめてから先へ進む。

- `scripts/factdiff.py 旧 新` — 二つの章ファイルから、数字(桁区切り・小数・%・年・時刻を含む)、カタカナ語(二文字以上)、英字列、「」内の語を抜き出し、新にあって旧にないもの、旧にあって新にないものを列挙する。-check に置いた表記の対応表(「約4割」↔「およそ40%」のような揺れ)を読んで、対応する組は差分から除く。
- `scripts/voice.py 章 [--compare]` — WRITING.md 4節2(a)の測定。本文(見出し・目次・表・図の行と説明・注を除く)と注を分けて、文数、平均文長と散らばり、文末の分布(である/だ/た/る・い/敬体/体言止め)、段落数と平均・最長段落長、一人称・括弧・ダッシュの千字あたりの回数、冒頭段落の型(場面/数字/地図/問い/引用/その他)を出す。`--compare` は authors/index.md を読み、同じ測定を全章と archive/v1/ の全章に掛けて、指定章から各章までの距離(文末分布の差の和と、標準化した文長の差の和)を近い順に、著者名とともに出す。
- `scripts/tenken.py` — 点検役に渡す文面を組む。三つの用法。
  - `tenken.py mekakushi 章 [--key 答えファイル]` — authors/声の設計表.md から全著者の名前と声の軸(文体・文の長さ・文末の偏り・一人称・言い切り・脱線・冒頭の型・締めの型)だけを読む。専門・音叉・解禁は渡さない。章から本文の段落三つ(冒頭の節・中ほどの節・終節から各一つ。図の行と説明、表、見出し、プロフィールは抜かない。【注N】の合図は落とす)と注一つ(声の段があるもの)を抜く。当て馬として、authors/index.md で別の著者に割り振られた章のうち -check に「改稿:」の記録があるものから本文の段落二つを抜く(無ければ当て馬なし)。全部を無作為に並べ替えて番号を振り、点検役への依頼の一文と答えの書式を添えた文面を stdout に出す。番号と出所の対応表は --key のファイルに書き、stdout には含めない。
  - `tenken.py shogo 章 節 [--taisho]` — 設計表の当該著者の行、その著者の文体カードの全文、文体台帳の全文、当該節の本文と注を、一つの文面に組む。--taisho を付けると末尾に「対照を求める」と足す。
  - `tenken.py sample 段落ファイル…` — 工程A用。設計表の声の軸と、著者ごとの試し書きの段落(ファイル名に著者のローマ字名を含める)から、目隠しの文面と答えを組む。
- `.claude/agents/geostudy-mekakushi.md` と `.claude/agents/geostudy-shogo.md` — 点検役の定義。リポジトリに同梱してある。どちらも tools を TodoWrite だけにしてファイルを読む道具を持たせず(allowlist を空にするとサブエージェントは起動しないので、害のない道具を一つ置いてある)、omitClaudeMd で CLAUDE.md も渡さない。動作を確かめる: 既存の章で `tenken.py mekakushi` を組み、目隠し役に渡し、書式どおりの答えが返り、汚染と言われないこと。
- archive/v1/ を作る(無ければ)。

## 3. 工程A 声の設計

1. authors/声の設計表.md を、11人ぶん一度に埋める。一人ずつ作らない。第4版の実測(表のファイルに書いてある)から離す。
2. 距離の条件(WRITING.md 5節)を満たすまで組み替える。敬体の著者・留保する著者・脱線する著者を各一人以上。音叉は系統を散らす。
3. 声はレンズと矛盾しない範囲で振る。専門・経歴・筆が乗る話・やらないことは、原則として変えない。変えるのは声の欄だけである。ただし第4版のプロフィールに書かれた声の言葉(「断定を恐れない」「文は短め」など)は、設計表に合わせて書き直す——第4版のそれは、実測と合っていなかった。
4. 場の制約: どの声でも段落は目安400字まで。文の長い声には短い段落を。
5. 著者の正本(authors/*.md)を書き直す。声の欄は、読者ふたりが引用を聞いて分かる言葉で数行。楽屋の具体値は文体カードへ。
6. 文体カードを書き直す。声の欄、音叉(系統つき)、台帳からの解禁(一項目まで)、この声を出す具体の手。「観測された癖」の欄は残す——レンズ側の癖は今後も有効である。代表章の指名は、改稿済みの章ができるまで空欄でよい。
7. 設計の段階の目隠し: 各著者につき、設計表の声で試しに書いた段落を一つずつ(題材は任意、事実は書かなくてよい。ただし著者の専門の題材は避ける——題材で当たっては検査にならない)ファイルに置き、`tenken.py sample` で文面を組んで目隠し役に渡す。11人中8人以上当たるまで設計に戻る。当たらなかった組が、設計表を組み替える材料である。
8. 依頼者に設計表・正本・文体カードを見せ、確認を得てから工程Bへ。正本の書き換えを章の写しに反映する作業(bash)は、章を改稿するときにその章ごとに行う。

## 4. 工程B 試作

- 著者を一人選ぶ: 振り幅が最も大きく、章が二つ以上あり、読書会で読みかけの章を持たない者。読みかけの章は依頼者に聞く。
- その二章を5節の規則で改稿し、6節の検査を全部通す。この試作で、照合役の指摘の粒度と、目隠し役の当たり方を見る。照合役が毎節「否」を出すなら、設計表の値が書き手に写せていないか、規定が曖昧かのどちらかで、後者なら設計表の語彙を直す。
- 読書会で読める段落かどうか、依頼者に確かめる。読みにくければ設計に戻り、その著者の行を直してやり直す。
- 通ったら工程Cへ。この二章は本改稿に数える。

## 5. 改稿の規則(一章ごと)

- 読むもの: CONCEPT.md、WRITING.md、その章のシリーズの series.md、著者の正本・文体カード・設計表のその行、その著者の改稿済みの章2本(無ければ試作章)、旧版の章と -check。読む量は定数に保つ。
- 版の保存: 旧版を archive/v1/text/<series>/<name>.md にコピーする(初回のみ。同名があれば済み)。旧版の -check も同じ場所に写す。旧版の img/ は共有でよい。
- 手順: 旧版を一節ずつ読み、同じ節を、同じ段落数で、その著者の声で書き直す。一節書き直すごとに `tenken.py shogo 章 節` で文面を組み、照合役に渡し、指摘を全部処理してから次の節へ進む。最初の節と終節は `--taisho` を付けて捨て札も見る——差が小さければ、まだ動いていない。図の行と説明文は据え置く(声で言い直してよいが、図を開かなくても通じる具体性は落とさない)。プロフィール表・位置の図・目次の写しは変えない。
- 事実: 足さない。落とさない。旧版が言っている数字・固有名詞・年・出典を全部残す。どうしても声に載らない事実は落としてよいが、-check に「落とした事実」として理由つきで残す。新しい事実を足すのは禁止——検証していない言い回しが混じる事故は、ここで起きる。factdiff の「新にあって旧にない」は、-check の対応表で読み替えられる表記の揺れを除いてゼロでなければ出さない。
- 構成: 節の数・題・順を変えない。段落の数を変えない——読書会の栞は段落の番号で位置を指している。400字を超える段落を割らざるを得ないときだけ増やしてよく、その場合は -check に新旧の段落の対応表を残す。
- 注: 番号と数を変えない。各注を、声の段と出典行に分ける(WRITING.md 2節)。声の段は、本文が言わなかったこと——「なぜ」の答え、拾う話題、著者の見立て——だけ。本文の数字の再掲と「〜は○○による」の帳簿は -check の検証記録へ移す(-check に無ければ足す。検証は済んでいるので、記録を移すだけでよい)。出典を示すほかに言うことのない注は一行にする。旧版の注が持っていた「なぜ」の答えは、一つも落とさない。
- 章の独立、他章への参照の禁止、安全のための断り書きの禁止は、従来どおり。
- プロフィールの写しは、書き直した正本からbashで入れ直す。
- -check の先頭に「改稿: 日付 第2版(声の改稿)。設計表の行: …。落とした事実: …。段落の対応: …。検査2の結果: …」を足す。執筆日と検証記録は残す。
- 文体カードの更新記録に一行足す。代表章が空欄なら、この章を指名する。

## 6. 検査(一章ごと)

1. factdiff: 新にあって旧にないものが、表記の揺れを除いてゼロ。旧にあって新にないものが、-check の「落とした事実」と一致する。
2. voice.py --compare: 最近傍が自分の著者の改稿済み章であること。archive/v1/ の章(自分の著者の旧版を含む)が最近傍なら不合格——旧の声が残っている。
3. 目隠し: `tenken.py mekakushi 章 --key 答え` を目隠し役に渡し、答えと突き合わせる(WRITING.md 4節2(b))。自分の四つのうち三つ、当て馬は自分に帰されないこと。
3'. 照合: 終節をもう一度照合役に掛け、指摘が無いこと。
4. 段落: 最長段落が目安を超えていない。
5. 通読: 事実の通り。「なぜ」が閉じている(改稿で答えが消えていないか)。台帳と臨時規則の照合(解禁項目を除く)。
6. site/build.py が警告を出さない。

結果を -check に記す。

## 7. 工程C 本改稿の順序

- 著者順に進める。一人の全章を続けてやり、次の著者へ。章順(州順・シリーズ順)ではやらない。理由: 声は連続して書くうちに定まり、文体カードに積める。
- 著者の順は、試作の著者、次いで authors/index.md の著者一覧の順。ただし、読書会で読みかけの章を持つ著者は最後に回す。
- 一つの章は一度しか触らない。著者の途中で設計表を直したくなったら、直してよいが、その著者の改稿済みの章を全部やり直す。
- 一人分終わるごとに納品し、報告する: 声がどう変わったか(voice.py の前後)、落とした事実、段落の対応、目隠しの結果、直したい点を見つけたが直さなかった箇所。マージは依頼者の指示を待つ。
- ブランチは著者ごとに切る。mainには直接コミットしない。

## 8. 工程D 締め

- archive/v1/ に44章と -check、第4版の authors/ が揃っていること。git のタグ(v1-before-voice-rewrite)を依頼者に提案する。
- 文体台帳の更新記録に、改稿の過程で観測された全著者共通の癖を載せる。少なくとも次の二つは第4版で観測されている: 章を「今日も/今夜も/まだ〜している」で閉じる型(44章中11章)、人の営みを「薄い層」と呼ぶ像(三章・二著者)。
- site/build.py でサイトを再生成する。
- 読書会への引き継ぎを依頼者に報告する: 読了済みの章は旧版で読まれたこと、既存の転写の照合(場の道具の check)は旧版に対してしか通らないこと、旧版の所在が archive/v1/ であること。

## 9. やってはいけないこと

- 工程の順序を変える。設計表を埋めずに章から始める。
- 事実を足す。構成を変える。段落を減らす。
- 章の途中で声を変える。
- 章順で進める。
- 注を声の段にするときに、「なぜ」の答えを削る。
- 旧版を消す。
- 声を振るために、読みにくくする。
- 点検役に渡す文面に、著者名・章名・自分の説明を足す。tenken.py の出力をそのまま渡す。
- 点検役に直させる。捨て札を紙面に使う。
- 照合役の指摘を、処理せずに次の節へ持ち越す。

## 依頼文の雛形

工程Aを始めるセッションに貼る文面。

> geostudy の文体改稿を始めてください。まず CONCEPT.md → WRITING.md → docs/文体改稿の手引き.md をこの順で読み、手引きの工程0と工程Aを進めてください。文体の点検は、.claude/agents/ の二つのサブエージェント(geostudy-mekakushi と geostudy-shogo)に、scripts/tenken.py が組んだ文面をそのまま渡して行ってください。工程Aが終わったら、設計表・著者の正本・文体カードを見せて、確認を求めてください。章にはまだ手を付けないでください。

工程C(著者一人分)のセッションに貼る文面。著者名だけ差し替える。

> geostudy の文体改稿の続きです。著者は「○○」。CONCEPT.md → WRITING.md → docs/文体改稿の手引き.md をこの順で読み、手引きの5〜7節でこの著者の全章を改稿してください。節ごとに照合役(geostudy-shogo)、章ごとに目隠し役(geostudy-mekakushi)に、scripts/tenken.py の文面をそのまま渡して点検してください。読書会で読みかけの章は「△△」です(無ければ「ありません」)。一人分終わったら報告してください。
