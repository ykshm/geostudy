# ロシア83連邦主体の執筆セッション 手引き

第4シリーズ「ロシア83連邦主体」の章を、セッションごとに一章ずつ書くための手引き。紙面に関する決まりはすべて CONCEPT.md / WRITING.md / text/russia/series.md が正本であり、本書は繰り返さない。本書が定めるのは、一回のセッションの範囲と工程、依頼の文面だけである。

## 依頼文の雛形

新しいセッションに貼る文面。連邦主体の名前だけ差し替える。

> ロシア83連邦主体シリーズの新しい章を書いてください。連邦主体は「○○」。
> まず docs/ロシア83連邦主体の執筆セッション手引き.md を読み、そこに書かれた工程で進めてください。
> 著者の提案など、確認事項があれば質問してください。

連邦主体を決めていない場合は、一行目を「連邦主体はあなたが提案してください」に置き換えてよい。その場合セッションは、候補と選んだ理由を示し、確認を得てから書き始める。

## 一回のセッションの範囲

- 原則、一連邦主体一セッション。章は分量が大きく、検査と図版まで含めると一つで十分に重い。
- 成果物は WRITING.md 1節6項の通り——章ファイル/-checkファイル/img/ の画像/著者を新しく立てたなら authors/ の正本と割り振りの一覧の行。
- ウェブ版の地図(site/MAPS.md)は執筆とは別の後工程である。章のマージ後に、下の雛形で別に依頼する(同じセッションに余力があれば続けてもよい)。

## 工程

1. ブランチを切る(mainには直接コミットしない)。
2. CONCEPT.md → WRITING.md → text/russia/series.md → authors/index.md を、この順で読む。
3. 著者を決める——このシリーズでは、章ごとに都度、既存の著者を使うか新しく立てるかを提案し、依頼者の確認を得る(WRITING.md 1節3項)。担当著者のプロフィール・文体カード・章を読む(読む範囲と文体の仕組みはWRITING.md 1節3項・5節に従う——全章の読み直しはしない)。
4. 章を書き、検査する(WRITING.md 1節・4節)。
5. 図版を集める(下の出所と実務メモ)。位置の図とプロフィール表の備品を忘れない(series.md)。
6. site/build.py を実行し、警告が出ないことを確かめる(ビルドは検査を兼ねる)。
7. コミットし、pushし、PRを立てて報告する。マージは依頼者の指示を待つ。
8. マージ後、依頼があれば地図の工程へ(site/MAPS.md)。

## 図版の出所(ロシアの題材、2026-09調べ)

- 第一の出所は Wikimedia Commons(下の実務メモ)。ロシアは投稿者の層が厚く、コンテスト(Wiki Loves Monuments など)の蓄積もあって、地方の州でも写真が見つかりやすい。
- 大統領府サイト(kremlin.ru)は、サイトの全コンテンツをCC BY 4.0で公開している——ただしRIAノーヴォスチやTASSが権利を持つと表示された写真は対象外なので、一点ごとに配信元の表示を確かめる。他の政府系サイトにも同様のCC表示を持つものがあるが、サイトごとに規約を読んで確かめる(表示が無ければ使わない)。
- 革命前(帝政期)の写真・絵図・地図は保護期間満了のものが使える——特にプロクジン=ゴルスキーのカラー写真(1909〜1915年に帝国各地を撮影。原板は米国議会図書館の所蔵で、公開に制限なしとされている)は、地方の章の図版として使いでがある。
- ソ連時代の写真をパブリックドメインと思い込まない——ロシアの保護期間は延長・復活を経ており、報道機関(TASSなど)の写真は現役の権利物である。CommonsのPDタグをAPIで確かめる運用を守る。
- 極東の章(サハリン、沿海地方など)では、戦前の日本側資料も使える——国立国会図書館デジタルコレクションの樺太・シベリア関係のうち保護期間満了のもの。
- 米国政府の作成物はパブリックドメイン——NASAの衛星画像、CIA作成の地図など。位置の図や地形の図に向く。
- CCの集積: Flickr、Openverse。一点ずつライセンスを確かめる。
- 自作の図(位置図・地形断面・統計グラフ)を積極的に使う。

## 図版の実務メモ(Wikimedia Commons)

- 使えるのは、パブリックドメインか、再配布が許されたCCライセンスの画像だけ。ライセンスは Commons API(extmetadata)で確認し、感触で済ませない。CC BY / BY-SA は、説明の段落の末尾に作者名とライセンスを必ず記す(削除禁止)。
- 章の図版は、ダウンロードして text/russia/img/ に実体を置く(ウェブ版の地図の写真がURL参照なのとは扱いが違う)。
- APIと画像取得のUser-Agentは「geostudy-image-collection/1.0」の系統に、連絡先としてリポジトリURLを添える(例:「geostudy-image-collection/1.0 (+https://github.com/ykshm/geostudy)」)。連絡先が無いとrobot policyで弾かれることがある。
- レート制限は強い。失敗したら数十秒(しつこい場合は90秒)おいて再試行する。数秒の待ちでは足りない。
- サムネイルのURLは標準幅(320/640/800/1024/1280など)以外を指定すると429で弾かれる。原画像の幅より大きいサムネイル幅の指定も429になる(小さい原画像は原寸のURLを使う)。
- ロシアの被写体は、ファイルページの説明文がロシア語だけのことが多い。同名の別の町(ロシアには同じ名前の集落が多い)に注意して、撮影地を確かめる。
- 採否は必ず目視で確かめる——説明文と写真の中身が合っているか、場面が読めるか。取得の記録(ファイル名・作者・ライセンス)は -check ファイルに残す。
