# サイト生成の仕組み(site/)

`text/` のMarkdown正本から、GitHub Pages用の静的HTML(`_site/`)を生成する。読書会のあとに注釈などを読み返すための、人間の読者向けの窓である。読書会の場はこれまで通りrawのMarkdownを読む——このサイトは場の運用に一切関与しない。

## 原則: 正本不可侵

- 正本は `text/`・`authors/`・`README.md` のMarkdownファイルである。サイトの都合でこれらの書式を変えることはしない(front matterを足さない、画像記法に書き換えない)。
- 書式の解釈・変換はすべて `site/build.py` が吸収する。

## 変換規則

- `## N. 題` → 節見出し(`#sec-N` アンカー付き。章内目次からリンク)
- `### 注` 以下の `注N: …` の段落 → 注のスタイルで表示、`#note-N` アンカー付き(読み返し用)
- `図N: 一行の説明(パス)` + 直後の説明段落 → figure要素。画像ファイルが `text/usa/img/` にあれば埋め込み、なければ「画像は準備中」の枠と説明文のみ
- 章冒頭の著者名・プロフィール・目次 → 専用のスタイル
- トップページ = 章の一覧(`authors/index.md` の割り振り表から生成)+ `README.md` 全文

## サイトに載せないもの

`-check` ファイル(編集用の楽屋)、CONCEPT.md / WRITING.md(執筆用の指示書)、`authors/` のプロフィール正本、`series.md`。いずれもリポジトリでは公開されているが、読み物のサイトの動線には置かない。

## lint(ビルド失敗の条件)

ビルドは書式検査を兼ねる。以下でビルドが失敗する:

- 節見出しが `## N. 題` の書式でない/節番号が1からの連番でない
- 注番号が章内で1からの連番でない
- 章冒頭のプロフィールが `authors/` の正本と一字でも違う
- 割り振り表(authors/index.md)にある章の実体がない

画像の未収録は警告のみ(ビルドは通る)。

## 動かし方

- 自動: mainへのpushで `.github/workflows/pages.yml` が走り、Pagesへ配備される
- 手元: `pip install markdown && python site/build.py` で `_site/` に出力される
